ФИО: Чистотин Михаил Юрьевич.
Тема ДП(Р): Разработка веб-информационной системы агрегации и анализа вакансий из нескольких источников с поиском, фильтрацией и уведомлениями на почту.
Утверждена (распоряжением) от «06» апреля 2026 года № 18.01-17-156
Дата выдачи задания: «06» апреля 2026 г.
Исходные данные к работе (цель, задачи и объем исследования, предполагаемые методы и методики исследования и т.д.)
Цель: Разработать и внедрить программный комплекс (вебприложение) для централизованного поиска и просмотра вакансий, автоматического пополнения каталога из открытых источников (API HeadHunter и открытые данные портала «Работа России»), разграничения данных по источнику, а также для организации взаимодействия пользователей (соискатели, работодатели, модераторы и администраторы) в рамках единой платформы, с целью сократить время подбора вакансий и повысить актуальность отображаемых предложений о работе.
Технологии: 
Язык программирования: Python (версия согласно среде разработки, не ниже 3.10, на практике используется 3.14).
Вебфреймворк: Django 4.2.29.
API: Django REST Framework 3.16.1.
Документация API: drf-yasg 1.21.15, drf-spectacular 0.29.0.
Асинхронные фоновые задачи: Celery 5.6.2, брокер/кэш: Redis 7.2.1 (через библиотеку redis).
HTTPклиент и разбор HTML: requests 2.32.5, beautifulsoup4 4.14.3, lxml 6.0.2.
Работа с изображениями: Pillow 12.1.0.
Документы резюме: python-docx 1.2.0.
Уведомления: python-telegram-bot 22.6.
Конфигурация окружения: python-dotenv 1.2.2.
Платформа разработки и эксплуатации (локально): ОС Windows 11; клиентская часть – веббраузер (Яндекс браузер).
Инструменты:
Среда разработки: Visual Studio Code.
Система контроля версий: Git.
Виртуальное окружение: venv (входит в стандартную поставку Python).
Менеджер зависимостей: pip (совместимый с используемой версией Python).
Запуск и отладка: Django development server (manage.py runserver), при необходимости – скрипт совместного запуска компонентов (run_all.py).
Очередь задач: Celery worker, планировщик Celery Beat.
Контейнер брокера сообщений и кэша: Redis (сервер версии, совместимой с клиентом redis 7.2.1).
СУБД: SQLite (встроенная в Python; файл базы данных проекта).
Тестирование: pytest 9.0.2, pytest-django 4.12.0.
Нагрузочное тестирование (при использовании в работе): Locust (версия – по requirements.txt/locustfile.py в проекте, при отсутствии фиксации – указать фактическую).
Документация REST: встроенные Swagger UI и ReDoc (через drf-yasg).
Входные данные:
Данные внешних API: JSONответы HeadHunter (api.hh.ru) при выгрузке вакансий, справочников, описаний, данных работодателя; JSON/XMLструктуры открытых данных «Работа России» (opendata.trudvsem.ru) при импорте вакансий.
Учётные и профильные данные пользователей: логин, пароль, ФИО, контакты, сведения профиля соискателя (образование, опыт, навыки, ожидания по зарплате, город, метро и др.), сведения профиля менеджера (компания, контакты, логотип).
Файлы пользователей: изображения аватара, логотипа компании, загруженный файл резюме (Word), иные документы профиля (если предусмотрено моделью).
Данные форм: параметры фильтров на списке вакансий (регион, зарплата, формат работы, источник вакансии, расписание, тип занятости и др. по реализованным полям); данные создания и редактирования вакансии на сайте; данные жалоб и модерации; события календаря и собеседований; сообщения чатов.
Конфигурация среды: переменные окружения и файл .env (ключи API, интервалы синхронизации, параметры пользовательского агента для HH и др.).
Служебные данные: расписание периодических задач Celery Beat; кэш и блокировки в Redis; входящие обновления Telegram Bot API при обработке команд ботом (если бот включён в состав комплекса).
Требования:
Обеспечить публичный просмотр каталога вакансий с пагинацией и многосоставными фильтрами (в том числе отдельный выбор источника: только HeadHunter, только «Работа России», все внешние, только размещённые на сайте).
Обеспечить карточку вакансии с явным указанием источника, корректным переходом на внешнюю площадку для отклика, для вакансий HH – подгрузка подробного описания и отображение рейтинга работодателя (по реализованной логике); для «Работа России» – отображение структурированного описания и адреса для карт в соответствии с данными источника.
Реализовать фоновый импорт вакансий с заданной периодичностью: отдельные задачи для HeadHunter и «Работа России», с инкрементальным отбором новых записей по курсорам (время публикации или изменения) и ограничениями объёма за один запуск согласно настройкам.
Обеспечить устранение устаревших записей: для вакансий HeadHunter – проверка доступности через API и деактивация недоступных; для «Работа России» – проверка статуса и удаление из локальной базы вакансий, отсутствующих в источнике (по реализованным задачам).
Предусмотреть защиту от конкурентной записи в SQLite при параллельном импорте (например, глобальная блокировка очереди загрузки с повтором задачи при занятости).
Реализовать ролевую модель: соискатель, менеджер (работодатель), модератор, администратор – с разным набором доступных действий (размещение вакансий, отклики, чаты, жалобы, панель модерации и администрирования – по факту реализованных разделов).
Обеспечить REST API с сессионной авторизацией и документацией Swagger/ReDoc с ограничением доступа к документации для администраторов (как в проекте).
Реализовать уведомления по расписанию (например, напоминания о собеседованиях и заметках календаря) через фоновые задачи.
Обеспечить корректную работу в среде Windows: вывод служебных сообщений без ошибок кодировки при кириллице в консоли (обработка в командах импорта и агрегаторе логов).
Предусмотреть резервное копирование базы данных по расписанию (задача Celery), экспорт/восстановление – в объёме, реализованном в проекте.
Выполнить требования методических материалов к оформлению пояснительной записки, тестированию (функциональные и нефункциональные виды по ISO/IEC 25010) и приложениям (текст программы, руководство пользователя, сценарии испытаний).
